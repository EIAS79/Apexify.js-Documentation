# Canvas & `createCanvas` — overview {#00-create-canvas-overview}

<Callout tone="info" title="Core Node canvas entry point">
`await painter.createCanvas(config[, painterOpts])` allocates an `@napi-rs/canvas` surface, paints configured backgrounds and effects, and returns PNG bytes plus the effective canvas configuration.
</Callout>

## Signature & types

```typescript
await painter.createCanvas(
  config: CanvasConfig,
  painterOpts?: { resolveAssetRefs?: boolean }
): Promise<CanvasResults>;
```

`CanvasConfig` and `CanvasResults` are the primary configuration and result contracts for the Node canvas workflow. The `signature-types` heading remains canonical so legacy deep links continue to resolve after the DOC-3 component migration.

<Prerequisites>
- Apexify.js 6.0.0 installed in a Node runtime.
- An `ApexPainter` instance configured for buffer output.
- Explicit width and height for predictable production output unless an inherited image/video source determines them.
</Prerequisites>

## Minimal workflow

<Steps title="Create a canvas">
1. Import `ApexPainter` from `apexify.js`.
2. Create a painter with buffer output.
3. Call `createCanvas` with explicit dimensions and one primary fill.
4. Use `buffer` as the PNG output or composite additional image/text/chart content.
</Steps>

## Return value (`CanvasResults`)

<ComparisonTable leftLabel="Field" rightLabel="Meaning" rows={[{"feature":"buffer","left":"Buffer","right":"PNG bytes for saving, output, or later composition"},{"feature":"canvas","left":"CanvasConfig","right":"Effective configuration reference after inherited sizing or other mutations"}]} />

<Callout tone="warning" title="Configuration mutation">
The returned `canvas` value is the configuration reference used by the creator. Features such as inherited background sizing can update effective width or height.
</Callout>

## Defaults and validation

<FeatureMatrix rows={[{"feature":"width / height","status":"Defaults to 500 × 500","note":"Prefer explicit production dimensions unless another configured source determines size"},{"feature":"primary fill","status":"Mutually exclusive","note":"Use at most one of colorBg, gradientBg, or customBg"},{"feature":"opacity","status":"0 through 1","note":"Values outside the range are invalid"},{"feature":"zoom.scale","status":"Greater than 0","note":"Required when zoom is configured"},{"feature":"bgLayers","status":"Validated per entry","note":"Supports configured color, gradient, image, pattern, preset-pattern, and noise layers"}]} />

<DecisionGuide items={[{"when":"you need a predictable banner or card size","use":"explicit width and height","because":"the output dimensions remain independent of source-asset dimensions"},{"when":"the background image should determine canvas size","use":"customBg.inherit","because":"the loaded image can supply effective dimensions"},{"when":"you need layered composition","use":"bgLayers","because":"layers make paint order explicit instead of overloading the primary fill"}]} />
