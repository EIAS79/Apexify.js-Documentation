## Composition model

Simple imperative flows are typically:

1. `createCanvas()` → `CanvasResults` base raster.
2. `createImage()` / `createText()` / `path2d.custom()` / `path2d.draw()` → new PNG buffers.
3. `save()` for files, or `toOutput()` for explicit constructor-selected encoded output.

`outPut()` remains only as a deprecated compatibility alias for `toOutput()`.

For declarative multi-layer stacks (charts, nested surfaces, one-shot PNG/GIF/video), use [Scene overview](/docs#00-scene-composition) with `createScene`, `renderScene`, `renderSceneToGIF`, and `renderSceneToVideoFrames`.

For reusable composition, use [Composition hub](/docs#00-composition-hub): templates, named assets, built-in scene-layer components, plugins, and explicit `$asset` resolution rules.

## Performance intuition

- `createImage()` filters and transforms can be native/raster intensive; dimensions dominate memory/cost.
- `pixels.getData()` / `pixels.manipulate()` are appropriate for explicit pixel work but scale with touched pixels.
- `batch()` runs independent jobs with bounded concurrency; `chain()` runs sequentially and feeds output forward.
- scenes/templates can avoid awkward repeated imperative composition; nested surfaces composite directly rather than requiring a PNG encode/decode boundary at each nesting level.
- generated GIF `AsyncIterable` frames preserve producer backpressure rather than collecting all generated frames first.
- remote video is staged by streaming into isolated temporary files.

Use [Performance & memory](/docs#03-performance-memory) before increasing concurrency or resource ceilings.
