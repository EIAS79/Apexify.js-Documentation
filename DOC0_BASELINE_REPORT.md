The current documentation architecture remains strongly client-oriented and hash-centric. All 148 documentation items are selected through `/docs#<document-id>` rather than owning canonical App Router routes.

### Current navigation/data flow

The baseline flow is:

```text
app/api/docs/route.ts
  -> curated folder metadata + filesystem MDX loading
  -> app/docs/page.tsx fetches /api/docs
  -> DocSidebar independently fetches /api/docs
  -> current document selected by URL hash
  -> MDX rendered client-side
```

This duplicate tree fetch and hash identity are baseline facts for DOC-1 to replace deliberately, not assumptions.

### Current search model

- endpoint: `/api/docs/search`
- source: `content/docs` filesystem
- index: none; recursive runtime scan
- ranking: filename, then folder, then content
- maximum results: 20
- result navigation: `/docs#hash`
- measured `canvas` query endpoint times: `12.9 ms`, `9.1 ms`, `10.8 ms`
- median: `10.8 ms`
- incremental JS after opening/using search: `0` bytes because search code is already in the initial docs client graph

## 12. Critical runner security finding

`DOC0-SEC-001` is the most serious finding in the baseline.

Observed facts:

- Gallery/Studio execution is enabled by default unless explicitly disabled;
- the runner secret is optional;
- snippets are guarded by a source-text blocklist, not an isolation boundary;
- user imports are hoisted and allowed;
- a user-derived snippet is executed in a child Node process;
- the child inherits the application environment;
- execution uses the application working directory.

Therefore the current runner must **not** be described or treated as a strong security sandbox for arbitrary untrusted public code. DOC-0 records this without changing current Studio/Gallery behavior. Hardening belongs to the relevant future documentation phases with explicit security review.

## 14. Preservation requirements

The baseline records fourteen non-negotiable preservation controls:

1. retain the existing docs corpus until coverage decisions are explicit;
2. map every `/docs#...` document identity and alias before retirement;
3. preserve deep heading identities or provide aliases;
4. preserve sidebar, breadcrumbs, pager, reading progress, TOC, and mobile navigation behavior;
5. preserve keyboard search and result navigation before replacement;
6. preserve code/copy/switcher/preview/Studio example affordances;
7. preserve Gallery sources, snippets, outputs, filters, details, and generation;
8. preserve Studio editor, execution, preview, session, and error behavior;
9. preserve light/dark/system theming and improve contrast rather than regress it;
10. preserve desktop/tablet/mobile usability and overflow behavior;
11. preserve existing semantics/focus/labels while fixing accessibility debt;
12. preserve inbound/public links and avoid duplicate indexable old/new pages;
13. do not document Phase 15+ roadmap APIs as shipped stable APIs;
14. retain or supersede exact package/docs drift guards.

These controls are the formal gate preventing later phases from calling destructive redesign “cleanup.”
